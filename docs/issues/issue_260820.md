## 2026-08-20 追加確定事項・既存記載の更新

### 1. 初期植物マスタの件数配分更新

既存の件数配分に「花もの」を追加する。

親レコード数の目安は以下とする。

- 観葉植物：25〜30件程度
- 花もの：25〜30件程度
- ハーブ：20〜25件程度
- 菜園：15〜20件程度
- 果樹・果物：10〜15件程度
- 多肉植物：5〜10件程度
- 洋ラン：5件程度

花ものはホームセンター・園芸店等で一般的な流通種類が多いため、
観葉植物と同程度の件数を目安とする。

この配分では親植物のみで概ね105〜135件程度となるが、
総件数を100件前後に収めること自体は目的としない。

管理上分ける意味のある子分類は別途追加し、
件数上限を理由に必要な分類を削除しない。

洋ランの初期候補は以下5種を基本とする。

- 胡蝶蘭
- シンビジウム
- デンドロビウム
- カトレア
- オンシジウム

### 2. `plant_category` の確定

`plant_category` は植物学上の生育形態ではなく、
一般ユーザーが園芸上どの用途・売り場・名称で認識するかを表すカテゴリとする。

初期値は以下とする。

- `foliage`：観葉植物
- `flower`：花もの
- `orchid`：洋ラン
- `herb`：ハーブ
- `vegetable`：野菜・家庭菜園
- `fruit`：果樹・果物
- `succulent`：多肉植物
- `other`：その他

現行の `tree` は `plant_category` から削除し、
植物の生育形態は `growth_form` で別管理する。

### 3. `growth_form` の追加

`plants` に生育形態を表す `growth_form` を追加する。

値は以下とする。

- `herbaceous`：草本
- `shrub`：低木・灌木
- `tree`：木本・樹木
- `vine`：つる性
- `other`：その他
- `unknown`：不明

球根・着生・グラウンドカバー等は別の分類軸であるため、
現時点では `growth_form` の値として追加しない。

初期seedでは原則すべての植物について設定する。

DB定義は `NOT NULL` とする方向で進める。

### 4. 名称・表記揺れと `aliases`

`plants.name` には、園芸流通・園芸情報サイト等で一般ユーザーに
最も認識されやすい代表名称を登録する。

別名・漢字表記・一般的な別表記に対応するため、
`plants` に以下のカラムを追加する。

`aliases text[] not null default '{}'`

例：

- `name = ローズマリー`
  - `aliases = {マンネンロウ}`

- `name = アラビアンジャスミン`
  - `aliases = {マツリカ, 茉莉花}`

初期seedで別名辞書を網羅することは目的とせず、
一般的に使用される主要な別名のみ登録する。

ユーザー個別の呼称については `user_plants.nickname` で対応する。

`aliases` 自体には一意性を要求しない。
同じ俗称・別名が複数の植物を指す可能性があるため、
検索時に複数候補が返ることを許容する。

別名検索は、既存植物を別名で検索した際の発見性向上と、
`plant_master_requests` における重複申請防止にも利用する。

### 5. 親・子レコードの最終判定ルール

植物マスタの階層は最大2階層とする既存方針を維持する。

子レコードは、複数の信頼できる園芸情報において、

- 水やり
- 用土
- 日照
- 栽培環境
- 耐暑性・耐寒性
- その他niwa.logの栽培支援上重要な管理条件

等に、継続的かつ実用上意味のある差が確認できる場合に作成する。

植物分類学上の違いだけでは子分類を作らない。

また、個別品種（cultivar）の違いや軽微な管理差だけを理由として
別レコード化しない。

管理方法が実質的に同じ場合は親レコードのみとする。

例として、ラベンダーについてはイングリッシュラベンダー、
ラバンジン、フレンチラベンダー等で管理差が大きいため
子分類を作成する。

### 6. 植物情報の参照元・採用ルール

初期seed作成時の情報源は、概ね以下の優先順位とする。

1. 種苗会社・植物生産者・園芸メーカー等の園芸情報
2. 大手園芸メディア・園芸ポータル
3. ホームセンター・ナーセリー・植物販売店等の育て方情報
4. 植物園、農業・園芸系研究機関等の信頼できる専門情報

個人ブログ、SNS、匿名投稿等は初期seedの根拠として使用しない。

1植物につき、原則2〜3ソース程度を確認する。

複数ソースの内容が概ね一致している場合は、
共通して確認できる傾向を採用する。

管理方法について重要な矛盾がある場合は3〜5ソース程度まで確認範囲を広げ、
以下の条件差によるものではないかを確認する。

- 鉢植え / 地植え
- 季節
- 生育期 / 休眠期
- 地域・気候
- 親分類 / 特定品種

矛盾する記述を機械的に平均して数値化しない。

解消できない場合は不必要な精密化を避け、
代表的・保守的な値を採用し、条件差は `watering_notes` 等へ残す。

production DB の `reference_url` には代表的な1URLを保存する。

一方、seed作成時の調査ログには、
実際に確認したすべてのURL、採用理由、数値化理由を保存する。

### 7. 水やり調査ルールの補足

`preferred_moisture_level` の5段階について、
園芸記事の個々の文言をbandへ機械的に対応させる詳細な変換表は作成しない。

複数ソース、アンカー植物、植物間の相対比較をもとに
調査時に総合判断する。

`watering_amount` は実際の給水量を定量的に表す値ではなく、
植物ごとの基本的な給水特性を以下の3段階で表す
定性的な補助パラメータとする。

- `light`
- `moderate`
- `heavy`

実際の必要水量は鉢サイズ・用土・栽培方法・株の状態等に依存するため、
本項目について厳密な数値化・詳細な変換基準は作成しない。

したがって既存コメント末尾の以下2項目は、
今後の未確定タスクとはしない。

- 園芸情報上の典型表現を各bandへ対応させる詳細な判定表
- `watering_amount` の定量的・詳細な判定基準

引き続き未確定なのは、
各moisture bandの具体的なアンカー植物および基準値とする。
