## 備考・気づき

- ローカルDBとSupabaseは別物：バックエンドはローカルのDocker PostgreSQLに繋いでいるが、認証はクラウドのSupabaseプロジェクトで行っている。そのためSupabaseのユーザーUUIDはローカルDBには存在せず、そのままSELECTしても0件になる
- Docker Composeの匿名ボリューム（`- /app/node_modules`）は、コンテナを作り直しても既存のものが再利用される。イメージ側のnode_modulesを反映させるには`-V`で明示的に作り直す必要がある
- `docker exec`でコンテナ内`npm install`した内容はイメージには残らない。依存を追加したら`--build`でイメージを作り直すのが本筋
- `await`は`async`が付いた関数の中でしか使えない（付け忘れると構文エラーでプロセスごと落ちる）
- `client.query()`の第1引数はSQL文そのもの。`SELECT`系だけでなく`BEGIN`／`SET LOCAL`のように「接続の状態を操作する」種類のSQLもある
- `$1`／`$2`は第2引数の配列の0番目／1番目に対応する。値をSQL文に直接埋め込まないことでSQLインジェクションを防いでいる
- 認証ミドルウェアはDBに触らない（`req.user`に積むだけ）。DBアクセスは`queryAsUser`の責務で、両者を繋ぐのはルートハンドラ、という役割分担になっている
