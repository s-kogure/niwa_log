## 備考・気づき

- PostgreSQLのRLSはテーブルオーナー／スーパーユーザーには適用されない（`FORCE ROW LEVEL SECURITY`を指定しない限り）。「RLSを有効にしたのに効かない」という気づきにくい状態になる
- 今回の方式の設計上の意味：アプリ側のコードに所有者チェック（`WHERE auth_user_id = ...`）を一行も書かなくても、DBレイヤーで漏れなく弾かれる。`WHERE`句の書き漏らしがそのまま情報漏洩になる設計を避けられる
- 依存関係の作業は「どのパッケージを使うかの宣言の整理」と「入っているバージョンの更新（脆弱性対応）」の2種類があり、別の話として区別して説明したほうがよい
- `package.json`は手で編集してよいが、`package-lock.json`と`node_modules`は手で触らない。`package.json`を直してから`npm install`で追従させるのが基本
- `npm audit fix`は`package.json`で宣言済みのバージョン範囲内での更新なので、破壊的変更を伴わない
- コメントを消すときは、直下の実行コードまで巻き込んでいないか確認する（今回`pool`の生成行を消してしまった）
