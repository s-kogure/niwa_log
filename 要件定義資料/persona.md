# niwa.log ペルソナシート

> GPTへの設計資料引き渡し・画面設計の判断基準として使用する。
> v1開発対象のメイン2名＋将来参照用のサブ1名。

---

## ペルソナ1（メイン）：えりちゃん

- 40代独身女性、神奈川県南部在住
- 賃貸の庭を活用して、一年草・多年草・家庭菜園の地植えと低木系ハーブの鉢植えを楽しんでいる
- 中級者。品種もそこそこ増えてきている
- **悩み**：お世話のつもりで水をあげすぎてしまう。過去にラベンダーを枯らした経験あり
- **アプリへの期待**：水やりの「あげすぎ」を防ぎたい。スコアで客観的に判断できると安心できる

### ユーザーストーリー

- とりあえずお世話した気になりたい。調子が悪い子を見つけると水をだばだばあげてしまう
- 結果、乾燥を好む地中海系ハーブを枯らしてきた（ラベンダーの悲劇）
- 「お水をぐっと我慢できる」仕組みがほしい
- 天気予測や生育状況、過去の水やりログから判断材料は欲しいが、ログそのものより「あげるべきかどうか」の結論が確認できる方法が欲しい
- あげるべきでないときに「あげなくていいよ」という赦しをアプリからもらえると安心できる
- 「あげるかどうかを確認した」時点でお世話行動として成立しているので、確認→あげなかった、の流れ自体に達成感がある
- 報酬的な肯定アクション（バッジ・褒め演出等）は人による。設計上は入れる余地を残しつつ、v1では保留

### 利用シーン（想定）

- 毎朝ダッシュボードを開いて、今日水やりが必要な子を確認する
- 天気予報と連動して「今日は雨だからあげなくていい」が一目でわかる
- 個体ごとのメモで「最近元気ない」などの観察記録を残す

## ペルソナ2（サブ）：ベランダ菜園初心者

- 30代共働き、マンションのベランダ栽培
- バジル・ミント・シソなど「食べられる系」から入って楽しさに目覚めた
- ミニトマトにも手を広げ始めて、品種が増えてきた
- **悩み**：忙しくて毎日じっくり観察する余裕がない。「前いつ水あげたっけ」が頻発
- **アプリへの期待**：開いたらパッと「今日やること」がわかってほしい。管理対象は少ないが、一株枯らすダメージが大きい

### ユーザーストーリー

- 朝の出勤前、ベランダに割ける時間はだいたい5分くらい
- アプリ開いて「今日水やりが必要な子」だけ見たい。不要な子は見なくていい
- 必要な子がいたら水あげて、なければそのまま出勤。判断に迷いたくない
- 品種ごとの水やり頻度なんて覚えてない。バジルとミニトマトで違うの？レベル
- 週末にまとめて「今週ちゃんとやれてたかな」を振り返りたいけど、紙に書くのは続かなかった
- 天気予報見て水やり判断するほどマメじゃない。アプリが天気を加味してくれるなら最高
- 一株枯らすと「やっぱり私には向いてないのかな」ってなるから、枯らす前に教えてほしい

### 利用シーン（想定）

- 朝の出勤前にスマホでサッと確認、必要な子だけ水やりして出かける
- 週末にまとめて振り返り、来週の天気も見ながら段取りする

## 将来参照用ペルソナ：シニアガーデナー

> v2以降の機能（気象データ蓄積・傾向分析・シーズン計画）の需要を裏付けるペルソナ。
> v1では開発対象外。アクセシビリティ・バリアフリー方面の設計指針としても温存。

- 60代、定年後に本格的な庭いじりを開始
- 土地も時間もあるが、記憶力への不安から「去年の今頃なにしてたか」を振り返りたい
- 紙の園芸日誌から移行したい。検索性・天気との相関分析に期待
- **主軸**：日々の水やり管理より、シーズン単位の振り返りと計画

## 設計上の示唆（ペルソナ対比から）

### 水やりスコアリングに求める役割の対比

|              | えりちゃん                 | ベランダ菜園初心者           |
| ------------ | -------------------------- | ---------------------------- |
| 本質的ニーズ | あげすぎを止めてほしい     | あげ忘れを拾ってほしい       |
| スコアの意味 | 低い＝「我慢してOK」の赦し | 高い＝「今日あげて」のガイド |
| アプリの役割 | 抑制と安心                 | 効率とガイド                 |

→ 同じスコア機能で両方のニーズに応えられるが、UIの見せ方（低スコアをポジティブに伝えるか、高スコアだけを目立たせるか）で体験が変わる。ダッシュボード設計時の要検討ポイント。

### 保留事項

- 「あげなかった」の記録をどう扱うか（現仕様：記録しない → えりちゃんペルソナの達成感と矛盾する可能性。確認行動自体が成立しているならログ不要かもしれないが、UIレベルで要検討）
- 報酬的肯定アクション（バッジ等）の導入可否 → v1保留、UI設計時に余地だけ確保
